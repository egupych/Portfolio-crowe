# Crowe Uzbekistan — портфолио команды

Статический сайт без сборщика: `index.html`, `css/`, `js/`. Открывается как есть,
локально хватает любого статического сервера (`python -m http.server 4173`).

## Данные

`js/data.js` — сотрудники на русском, `js/data.en.js` — английские переводы по
ключу `id`. Сертификаты привязаны к `id` сотрудника, а не к имени, поэтому
переименование человека ничего не ломает.

## Скрипты

Порядок важен: картинки → страницы → проверка.

| Команда | Что делает | Когда запускать |
| --- | --- | --- |
| `python scripts/optimize-images.py` | Пережимает PNG из `photos/` и `certificates/` в WebP, которые и отдаются браузеру | добавили или заменили фото либо сертификат |
| `node scripts/build-pages.mjs` | Собирает `team/<id>/index.html` с мета-тегами сотрудника, а также `sitemap.xml` и `robots.txt` | изменили данные или `index.html` |
| `node scripts/check-assets.mjs` | Проверяет, что ключи сертификатов ведут к существующим сотрудникам и все файлы на месте | перед коммитом |
| `npm test` | Прогоняет тесты из `tests/` | перед коммитом |
| `npm run lint` | ESLint по всем модулям | перед коммитом |
| `npm run check` | Линтер, тесты и проверка ассетов подряд | перед коммитом |

Исходные PNG остаются в репозитории как архив — в вёрстке они не используются.

## Тесты и линтер

`npm run check` — линтер, тесты и проверка ассетов подряд. Для разработки нужен
`npm install`; сам сайт зависимостей не имеет и в выкладку `node_modules` не
попадает.

Тесты на встроенном в Node раннере, `tests/`:

- `data.test.mjs` и `i18n.test.mjs` — чистая логика: сборка поискового индекса,
  локализация, привязка сертификатов к `id`, целостность данных, паритет ключей
  между языками, латиница в путях к картинкам;
- `app.test.mjs` — интерфейс в jsdom: поиск, фильтры, роутинг, закладки,
  лайтбокс, переключение языка. `app.js` ничего не экспортирует, поэтому тест
  поднимает `index.html` в настоящем DOM и кликает по нему, как человек;
- `syntax.test.mjs` — `node --check` по всем модулям.

Что не покрыто: печать резюме и сертификатов (нужен реальный браузер), лупа в
лайтбоксе и вёрстка.

## Выкладка

`vercel.json` держит HTML, JS и CSS на `must-revalidate`, картинки — на неделю.
Поэтому в ссылках на скрипты не нужен `?v=`: после деплоя браузер сам заберёт
свежие файлы.

Там же `framework: null` и пустые `installCommand`/`buildCommand`: `package.json`
лежит в корне только ради линтера и тестов, собирать проект не нужно —
сгенерированные страницы уже в репозитории.

`.vercelignore` не пускает в выкладку исходные PNG (37 МБ) и инструменты
разработки. Браузер запрашивает только WebP.

Несуществующий адрес отдаёт `404.html` — то же приложение, человек попадает на
список команды, а не на ошибку сервера.

## Адреса

Профиль сотрудника живёт по `/team/<id>` — отдельная страница со своими
мета-тегами, её же подхватывает `js/app.js`. Старые ссылки вида `/#<id>`
продолжают работать и переписываются на новый адрес.
